# Installation

This guide builds the complete system on one Mac and one iPhone. Budget 20–30 minutes the first time because macOS and iOS permission prompts require manual confirmation.

## 1. Check the prerequisites

You need:

- A Mac with macOS 14 or newer. The core CLI uses only Python 3.11+, but the optional current `imsg` release requires macOS 14.
- Xcode Command Line Tools for the small Swift Contacts helper. Install them with `xcode-select --install` if `swift --version` fails.
- Messages signed into an iMessage account on the Mac.
- An iPhone on which messages sent to the configured address arrive, and iCloud sync enabled for Shortcuts.
- A domain whose DNS is managed by Cloudflare. Choose a dedicated hostname such as `iphone.example.com`.
- Homebrew, or equivalent manual installations of `cloudflared` and Python.

For the recommended remote workflow, install the current ChatGPT desktop app on the Mac and ChatGPT mobile app on the iPhone. OpenAI's [Remote connections guide](https://learn.chatgpt.com/docs/remote-connections.md) explains account and host requirements.

## 2. Clone and install

```bash
git clone https://github.com/samin100/codex-ios-assistant.git
cd codex-ios-assistant
brew install cloudflared steipete/tap/imsg
./scripts/install
```

`scripts/install` performs local, inspectable work:

- creates `.venv` and installs the checkout in editable mode;
- links `iphone` into `~/.local/bin`;
- compiles the Contacts helper and copies it into `~/.local/bin`;
- links the bundled skill into `~/.agents/skills/iphone-control`;
- starts the three-value configuration prompt if no config exists.

Make sure `~/.local/bin` is on your shell `PATH`. For zsh, this line in `~/.zshrc` is sufficient:

```bash
export PATH="$HOME/.local/bin:$PATH"
```

Open a new terminal or run `source ~/.zshrc` after adding it.

## 3. Configure the three private values

The installer runs this automatically the first time:

```bash
./scripts/configure
```

Enter:

- `IPHONE_MSG_TARGET`: your own iMessage email or phone number that reaches the iPhone;
- `IPHONE_PUBLIC_URL`: the dedicated Cloudflare HTTPS origin, with no path;
- `IPHONE_RECEIVER_TOKEN`: generated by the script and not displayed.

They are stored at `~/.config/codex-ios-assistant/config.env` with mode `0600`. They are intentionally outside the Git checkout. To change the target or hostname, rerun `scripts/configure`; to rotate the token, add `--force-token` and then regenerate the Shortcut.

Noninteractive configuration is also supported:

```bash
./scripts/configure \
  --target 'your-imessage-address@example.com' \
  --url 'https://iphone.example.com'
```

## 4. Create the stable Cloudflare Tunnel

```bash
./scripts/setup-cloudflare
```

On its first run, `cloudflared` opens a browser so you can authorize the correct Cloudflare account and zone. The script then:

- creates or reuses a named tunnel called `codex-ios-assistant`;
- creates the DNS route for your configured hostname;
- writes a local tunnel config to `~/.config/codex-ios-assistant/cloudflared.yml`;
- routes only that hostname to `http://127.0.0.1:8787`.

The random `trycloudflare.com` quick-tunnel hostnames are intentionally not used. A named tunnel plus your own DNS record stays stable across reboots.

Cloudflare documents the same named-tunnel sequence in [Create a locally-managed tunnel](https://developers.cloudflare.com/tunnel/advanced/local-management/create-local-tunnel/).

## 5. Install the background services

```bash
./scripts/install-services
```

This creates three per-user LaunchAgents and starts them immediately:

| LaunchAgent | Job |
| --- | --- |
| `io.github.codex-ios-assistant.sender` | Accepts local `hola …` commands and automates Messages outside Codex's sandbox |
| `io.github.codex-ios-assistant.receiver` | Listens only on `127.0.0.1:8787` for correlated responses |
| `io.github.codex-ios-assistant.tunnel` | Connects the public hostname to the loopback receiver |

Logs are written to `~/Library/Logs/codex-ios-assistant/`. The services start at login and are restarted if they exit.

The first real `iphone` command may trigger a macOS Automation prompt allowing the Python process used by the sender LaunchAgent to control Messages. Approve it in System Settings → Privacy & Security → Automation. If no prompt appears or the command fails, see [Troubleshooting](troubleshooting.md).

## 6. Place the Shortcut on the Mac clipboard

```bash
./scripts/copy-shortcut
```

This renders the sanitized action template with your private hostname and token, writes the ignored file `build/ios-assistant-actions.plist` with mode `0600`, and places 95 serialized action items on the general pasteboard.

Now perform these manual steps on the Mac:

1. Open Shortcuts.
2. Click `+` to create a new blank shortcut.
3. Name it `iOS Assistant`.
4. Click once in the empty action canvas.
5. Press Command-V exactly once.
6. Wait for all actions to appear, then close the editor so Shortcuts saves it.
7. Confirm iCloud sync is enabled for Shortcuts in System Settings → Apple Account → iCloud.

Do not paste the raw plist text. The script has already placed native Shortcuts action pasteboard items on the clipboard.

## 7. Let the Shortcut reach your tunnel

When the pasted Shortcut first posts screen text or a screenshot, iOS may ask whether the shortcut may access the hostname. Choose Allow. It may also request permissions for screenshots, on-screen content, alarms, clipboard, location-aware links, and other native actions as you exercise them.

The rendered Shortcut contains the receiver token. Treat the installed Shortcut and the ignored file under `build/` as private.

## 8. Create the personal Message automation on the iPhone

Personal automations are device-local, so create this on the iPhone even if the Shortcut has synced:

1. Open Shortcuts → Automation.
2. Tap `+`, then choose the Message trigger.
3. Set `Message Contains` to `hola`.
4. Restrict `Sender` to the identity used by your Mac/self-message setup when that identity is selectable.
5. Choose `Run Immediately` and disable confirmation/notification prompts offered by your iOS version.
6. Add the `Run Shortcut` action and select `iOS Assistant`.
7. Save the automation.

Apple documents that a Message personal automation can run automatically when configured without confirmation in [Enable or disable a personal automation](https://support.apple.com/guide/shortcuts/enable-or-disable-a-personal-automation-apd602971e63/ios).

Start with the sender restriction enabled for safety. If self-addressed messages are not represented as coming from that contact on your iOS version, temporarily remove only the sender condition and retest. Keep the `hola` content condition.

## 9. Verify every layer

First verify the Mac services:

```bash
iphone doctor
curl http://127.0.0.1:8787/health
curl "$(sed -n 's/^IPHONE_PUBLIC_URL="\(.*\)"$/\1/p' ~/.config/codex-ios-assistant/config.env)/health"
```

The local and public health checks should both print `codex-ios-assistant receiver up`.

Then exercise the one-way Message path:

```bash
iphone home
```

Messages should show a private `hola homescreen` message and the iPhone should return to the Home Screen. The CLI prints `Home Screen requested.` because this action has no response receipt.

Finally exercise correlated responses:

```bash
iphone screen read --timeout 30
iphone screen capture --timeout 45
iphone alarm list --timeout 30
iphone clipboard get --timeout 30
```

Screen capture prints the absolute path to an image under `~/.local/share/codex-ios-assistant/inbox/`.

## 10. Optional local data integrations

The Contacts helper is installed by `scripts/install`. macOS asks for Contacts access the first time it runs:

```bash
iphone contacts search 'Jane Appleseed'
```

For local Messages history and existing-group draft resolution, install the maintained `imsg` CLI (already included in the recommended Homebrew command above):

```bash
brew install steipete/tap/imsg
imsg chats
```

The [`imsg` README](https://github.com/openclaw/imsg) lists its current macOS requirements. Grant Full Disk Access to the terminal or host application running Codex so `imsg` can read `~/Library/Messages/chat.db`. Automation permission is not required for the project's `iphone messages chats`, `history`, `search`, or `group` commands because they are read-only.

There is no separate Find My dependency. `iphone find-my` opens Apple's `findmy://` URLs; person lookup by name uses the Contacts helper.

## 11. Set up ChatGPT Remote

To use the iPhone as the conversational interface while Codex and its tools remain on the Mac:

1. Install the current ChatGPT desktop app on the Mac and sign in.
2. Open Settings → Connections → Control this Mac or PC.
3. In the ChatGPT mobile app, open Codex and scan the QR code shown by the desktop app.
4. Keep the Mac awake, online, and signed into the same ChatGPT account/workspace.
5. Start or resume a Codex task from the mobile app and ask it to use the iPhone skill.

Remote sessions use the Mac's files, tools, permissions, and installed skills. See OpenAI's [Remote connections guide](https://learn.chatgpt.com/docs/remote-connections.md) for the current product steps and limitations.

## Updating or uninstalling

After pulling a new version:

```bash
git pull --ff-only
./scripts/install
./scripts/install-services
```

If the Shortcut template changed, run `scripts/copy-shortcut` and paste into a new blank Shortcut. Test the new copy before deleting the older one, then point the iPhone automation to the new copy.

To stop and remove only this project's LaunchAgents:

```bash
./scripts/uninstall-services
```

The script moves the plist files to the Trash so they are recoverable. It leaves configuration, logs, screenshots, the Shortcut, and Cloudflare resources in place.
